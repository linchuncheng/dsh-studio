## 1. 结论

1. **这不是「一眼 AI 味」的界面，而是一套有设计系统、但两套体系并存的界面。**
   项目里已经有 BoardUI（Tailwind v4 + token + accent ramp，Figma 为准）和一套手写 `.ds-*`（`client.src.js` 里 809 处），
   两套各自成立，合在一起才出问题：圆角 7 种、间距两套节奏、图标一边是线性图标一边是 emoji。
2. **slop 信号集中在四件事**：emoji 当图标（18 个不同符号，32 面全中）、字体从未真正加载、字号差 1px 的伪阶梯、
   胶囊化（297 个胶囊、253 个 999px chip）。unslop 点名的「紫色渐变 / 发光 / 渐变文字 / 循环动效」在本项目里**基本都是干净的**。
3. **布局与细节比文案强**：暗色对比度 0 失败、无渐变文字、无循环动效、无彩色发光（96 处阴影全是同一枚中性软阴影）。
   真正掉分的是文案层：卡片元信息成了一串符号、表头把 `rev 2285` 当文案、原始 `t-` 任务号上了卡面。

按 unslop 的判级：**Light slop（轻）**——主体是设计过的，只做 polish，不重做。

## 2. 方向（unslop 要求先定方向再动手）

- **产品**：给产品/架构/研发/测试四个角色交接需求的内部工作台，人在这里看 AI 把活推到哪一步、能不能放行。
- **性格**：克制、可核对、有值班感。不追「现代感」，界面是**证据板**，不是演示页。
- **世界**：车间看板 + 登记簿。项目本身充满编号、签字、门禁、快照、流水号，界面应该像**盖过章的单据**，
  而不是营销页。中性色偏一点冷灰（纸张与金属），强调色只给「该你动手的那一个」。
- **时刻（只允许两处变丰富）**：① 工作台顶部「今天要处理」——做成一块真正的**值班台**：一个大数字 + 一条
  趋势/积压走势，其余四张退成小卡；② 效能页的**周期分布**——一个画得认真的图，承担全站唯一的"数据之美"。
- **签名**：**序号 + 状态点**。所有可核对的东西（REQ/DEV/TEST 编号、rev、时间）用 mono + `tabular-nums` 统一；
  所有"当前状态"用一个 6px 圆点（颜色只表意），不再用 emoji 或彩色胶囊。

## 4. 九个系统性问题

### S1 字体从未真正加载（P1）
`web/src/boardui/theme.css:54` 写 `--font-sans: var(--font-inter), ui-sans-serif, …`，但它是从 Next.js 的
`next/font` 抄来的写法：全仓库**没有 `@font-face`、没有 Inter 资源、也没有 `--font-inter` 定义**。
实测 8008 个文本节点的 `font-family` 第一项就是 `ui-sans-serif` —— 设计系统选的字一个都没落地，
Windows 上是微软雅黑、macOS 上是 SF，同一张设计稿在两端不是同一个界面。

修法：二选一，别留假 token。① 自托管一个 Inter woff2（`--font-sans: 'Inter', system-ui …`）；
② 承认用系统字，把 token 改成 `system-ui` 并在 `docs/ui.md` 写明「不引入外部字体」。

### S2 两套设计系统并存（P1，结构性）
| | BoardUI（`web/src/boardui/theme.css`） | 手写 `.ds-*`（`client.src.js:377` 起） |
| --- | --- | --- |
| 间距节奏 | 4 / 8 / 12 / 16 **加** Tailwind `.5` 档（6 / 10 / 14） | 6 / 10 / 14 **加** 奇数值 11 / 15 |
| 圆角 | 控件 8 / 卡片 16 | 面板 10 / 控件 10 |
| 阴影 | `rgba(16,24,40,.05)` | `0 12px 32px rgba(0,0,0,.22)`（`client.src.js:2306` 新建菜单） |
| 图标 | 线性（lucide 已在依赖，仅登录页用了 2 个） | emoji |
| 字号 | 12/14/16 | 13 为基 |

修法：**认一套为基线**（建议 `.ds-*`，因为它覆盖 80% 的界面），把 BoardUI 的 token 映射进来：
`--ds-gap-1: 8px` 之类，Tailwind 侧只留工具类、不再自带语义色与阴影。

### S3 主按钮是「同色相明度渐变 + 内高光」（P2，需要一次判断）
32 个面里 32 个主 CTA（`＋ 新建`）实测 `linear-gradient(oklch(0.623 0.214 259.815) → oklch(0.546 0.245 262.881))`，
来自 `web/src/index.css:1736`。unslop 只允许"同一中性色内的轻微明度变化"，这里是一个**饱和强调色上的明度渐变**，
再加 theme.css:102 记的「inner top highlight + 1px inner blue edge」。这不像 AI 味，但它是"亮面塑料按钮"的语言。
建议：保留渐变（同为蓝 500→600，不是双色相），**去掉内高光与内描边**，让它变成一块平色。
另外「发表评论 / 发布 / 加成员」用的是 `linear-gradient(rgb(235,235,235) → oklch(.87 0 none))` —— 白色渐变按钮，
比主按钮更可疑，建议直接平色。

### S4 表情符号当图标，18 个符号，32 面全中（P1，改动面最大）
实测 18 个图形符号：👤 ☀ ☾ ⚠ 📋 🏛 🛠 🧪 📄 ☑ 📎 ⏰ ✅ ⛔ ❌ ⬜ ⏭ ▶ ✨。
每个面的出现次数：抽屉 28、看板 20、效能 13、需求 12、专家设置 10、用例 9、版本 8。
按来源分三档：

- **界面字符串里写死**（可直接换）：`client.src.js:256`（`☀ 明亮 / ☾ 黑暗`）、`:2240-2241`（`👤 超管 admin · 默认口令`）、
  `:2292`（`⚠ 集成异常`）；`web/src/studio/card.js:56/118/138/139`（`📄` 需求码、`⛔` 阻塞、`☑` 清单、`📎` 交付物）；
  `web/src/studio/drawer.js:123/905/907`（`✅❌⬜⛔`）、`:1585`（**`✨ 生成用例草稿`** —— unslop 点名的 "New ✨" 型符号）、
  `:1799`（`🤖` 兜底）；`web/src/studio/labels.js:13`（用例四态）、`pages/cases.js:198`。
- **专家数据字段**（要迁移数据）：`state.config.experts[].emoji` = `📋 🏛️ 🛠️ 🧪`，
  在 8 处渲染：`board.js:152`、`drawer.js:951/977/1799`、`mentions.js:35`、`palette.js:49/299`、`roster.js:28`。
  所以这不是"全局替换 emoji"能解决的，要按专家 `id/role` 映射图标。
- **状态符号**（应改成 6px 圆点 + 文字）：`☑ ✅ ❌ ⬜ ⏭️ ⛔ ⚠`。

修法：`web/src/studio/icons.js` 新建一个映射表（`emoji/role → lucide 图标名`），统一 16px / 1.5 描边；
状态一律 `点 + 文字`，颜色只表意。

### S5 语义色有 3 个硬编码红 + 1 个紫，中性灰 7 种（P1）
浅色实测文字色：中性 `#09090b`、`#18181b`、`#6b6b74`、`#71717a` + `oklch(.145/.556/.708)` + 60% 黑；
红 `oklch(.586 .253 17.585)`、`oklch(.637 .237 25.331)`、`oklch(.455 .188 13.697)`，**外加三处硬编码**：`#e5484d`（29 次）、`#c0392b`（12 次）、`#dc2626`（11 次）；
琥珀 `rgb(162,97,0)`、`oklch(.795 .184 86.047)`、`#d97706`（17 次）；绿 `#0f9d58`（29 次）。同一个"错误"在一页里可能有两种红。
还有一个**第二强调色**紫 `#8b5cf6`（10 次）与 `#7c3aed`（命令面板分类标签）—— 蓝色系之外的一整个紫系。

修法：中性留 3 个角色（primary/secondary/muted），语义色各组只留 1 个浅/深配对；`#6b6b74` 与 `#71717a` 差 6 个单位，
肉眼分不出但占两个 token —— 合并。

### S6 危险操作没有视觉语言（P1，功能性）
`web/src/boardui/theme.css:419` 定义了 `--gradient-button-danger-*`（8 条），
但 `grep ds-btn-danger` = **0 处使用**；实测「删除」按钮的背景是主色蓝 `rgb(37,99,235)`（32 面里 6 次）。
平台有 20 条破坏性路由（删数据/清审计/改权限/发布/回滚），界面上没有一种视觉告诉人"这一步会删东西"。

修法：`ds-btn-danger` 接上 token；`confirmDialog({danger:true})` 的确认键走 danger 变体；
列表里的删除仍用 ghost + `data-danger`，保持「轻入口、重确认」。

### S7 胶囊化：297 个胶囊，其中 253 个是 999px 的 chip（P2）
`web/src/index.css:254` 的 `.ds-chip` 是 `border-radius:999px; height:20px; font-size:12px`；32 面合计 **297 个**元素圆角 ≥99px（命令面板单面 49 个、效能 36、看板 29、抽屉 29）；
而面板与按钮是 10px。结果是「扁平面板 + 到处小胶囊」，形状语言不统一。
修法：chip 降到 6px（或 8px），只有 **当前选中态** 和 **6px 状态点** 保留全圆。

### S8 卡片元信息是一串符号（P1，文案/信息架构）
实测一张卡的副行：`📄 REQ-2026-002 · ☑ 0/3 · 📎 1 · ✅ 2/3 · 1 评论 · ⌥ 2 · t-f42acfd8`，部分还带 `⏰ 剩 145h`。
问题有四个：原始任务号 `t-f42acfd8` 上了卡面；`⏰ 剩 145h` 让人自己换算；`⌥ 2` 没有可读含义；
`☑ 0/3` 在 12 张卡上全部出现（自动生成的三条验收项），变成噪音。

修法：卡面只留两个可核对的事实 —— **负责人 + 门禁状态点**；其余（id、清单、交付物、用例、评论）进抽屉。
剩余时间改成日期或「今天/明天」。

### S9 表头把开发细节当文案（P2）
`12 个任务 · rev 2285 · 更新于 11-22 01:10`（`client.src.js` 页头）。`rev` 是内部 revision，人不需要每一屏看到它。
另外列头 `待澄清 1 负责人 未配置` 三行在 8 列里重复 8 次，而「未配置」是同一件事。
修法：`12 张卡 · 11-22 01:10 更新`，rev 移到 `title` 或诊断区；列头把「负责人」并到列名后面一行（`待澄清 · 1 · 产品经理`）。

## 10. 第二轮：把两套标尺合成一套

第一轮之后还剩两条"两套系统"的证据：`gap: 6px` 1044 处、14px 字号 588 处。
它们不是散落的坏习惯，而是 **BoardUI 那套标尺**：`--text-body-regular/medium/semibold`
全是 `0.875rem`（14px），间距用的是 Tailwind 的 `.5` 档（6 / 10 / 14）。

这一轮按"映射"而不是"重画"处理：

| 来源 | 处理 |
| --- | --- |
| `typography.css` 的 `--text-body-regular/medium/semibold` | `0.875rem` → `0.8125rem`（14 → 13），行高 1.25rem → 1.125rem |
| CSS 与内联 style 里的 `gap: 5/6/10/14px` | → 4 / 8 / 12 / 16（含 `gap: a b` 两值写法的第二个值） |
| 组件里的 `.5` 档工具类（`gap-1.5`、`gap-2.5`、`px-2.5`、`py-2.5`、`px-1.5`、`py-1.5`、`p-2.5`、`mt-1.5`、`mt-2.5`、`mb-1.5`、`space-x-1.5`、`space-y-1.5`） | 就地落到 4 的整数倍 |
| `select.tsx` 的任意值 `gap-[5px]` | `gap-1` |
| 残留的 6 处 `font-size: 14px`（`.ds-btn`、命令面板输入、`.ds-colrow-name`、`.ds-proj-name`、`.ds-pane-title`、markdown h3） | 13px；markdown h3 提到 16（保住 h3 与 h4 的层级） |

## 11. 第三轮：把 padding 也收进 4px 尺度

前两轮把 gap 与字号收口之后，非 4px 网格里剩下最多的就是 padding：
`padding-right/left: 10px` 各 395 处、`padding-top/bottom: 6px` 379/359 处，
另有 9 / 11 / 13 / 15 / 18 这类零散值。

处理方式是**吸附**而不是逐条挑：4 的倍数不动，2px 保留（unslop 明确允许的小控件微调），
`n%4==3` 加 1、`n%4==1` 减 1、`n%4==2` 补 2。这样既不会把 2px 的紧凑行撑开，
也不会因为缩紧而挤出新的换行。

| 位置 | 处理 |
| --- | --- |
| `index.css` / `client.src.js` 的 `padding`、`padding-*` | 数值吸附到 4 的倍数（121 处） |
| 同一批文件里的 `gap`、`row-gap`、`column-gap` | 同上（20 处，含残留的 9px） |
| 内联 `style={{ padding: '2px 10px' }}` | 同上 |
| 表格的 `@apply px-3 py-2.5` / `px-2.5 py-1.5` | `py-2` / `px-2 py-1`（表头表体的 padding 来自 `@apply`，上一轮扫组件类时漏了它） |

### 结果

| 指标 | 第二轮后 | 第三轮后 |
| --- | --- | --- |
| `padding` 10px | 395 × 2 | **0** |
| `padding` 6px | 379 / 359 | **0** |
| `gap` 9px | 77 × 2 | **0** |
| 非 4px 网格的剩余项 | padding 6/10、gap 9、gap 14 | **只有 2px**（`margin-top`、`gap`、`padding` 的微调）与 `margin-left: auto` 解析出来的 px |
| 文字截断 / 横向溢出 | 9 / 0 | **9 / 0** |
| 对比度失败 / emoji | 0 / 0 | **0 / 0** |

回归：`npm test` 378、`verify:pages` 45、`probe:panel` 29 全过。

### 为什么 2px 留着

unslop 的间距规则原文允许："A 2px step is fine for nudges inside small controls,
and an odd value that exactly centers something stays." 计数徽标、列表行里的图标间距、
`.ds-card-foot` 的 `gap: 2px 8px` 都属于这一类；把它们抬到 4px 只会让紧凑的行松散掉。

另外 `marginLeft=86px` 那 85 处是 `margin-left: auto` 被浏览器解析后的实际偏移，不是写死的值。
